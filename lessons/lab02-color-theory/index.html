Lab Color Theory

Discover how RGB LEDs create millions of colors, learn Active-Low logic — a hardware "gotcha" that trips up beginners — and write functions to control LED brightness with PWM.

Learning Objectives

By the end of this lab, you will be able to:

  1. Understand how RGB LEDs mix colors using red, green, and blue light.
  2. Write functions to create reusable color-control code.
  3. Grasp Active-Low logic — why 0 turns the LED ON on this board.
  4. Use PWM (Pulse Width Modulation) to control LED brightness.

Part 1: Understanding Active-Low Logic

On the Arduino Nano 33 BLE Sense Rev2, the onboard RGB LEDs use Active-Low logic. This means:

  • 0 (LOW) turns the LED ON
  • 1 (HIGH) turns the LED OFF

This is the opposite of what many beginners expect! It's a great "gotcha" moment to learn how hardware logic can differ from software logic.

🔬 Try It: Write a quick test program to verify Active-Low behavior:
Python — Active-Low Test 
import machine
import time

# RGB LED pins on the Nano 33 BLE Sense (nRF52840 pin numbers)
# Red = P0.24, Green = P0.16, Blue = P0.06
red = machine.PWM(machine.Pin(24), freq=1000)
green = machine.PWM(machine.Pin(16), freq=1000)
blue = machine.PWM(machine.Pin(6), freq=1000)

# Start with all LEDs OFF (Active-Low: 65535 duty = off)
red.duty_u16(65535)
green.duty_u16(65535)
blue.duty_u16(65535)

print("Testing Active-Low logic...")

# Active-Low: 0 = ON, 1 = OFF
red.duty_u16(0)       # Red ON (0 duty = full brightness)
time.sleep(1)
red.duty_u16(65535)   # Red OFF (65535 duty = no brightness)
time.sleep(1)

print("Red LED should have blinked!")

Part 2: PWM and Brightness Control

PWM (Pulse Width Modulation) lets us control LED brightness by rapidly turning the LED on and off. The duty cycle determines how much time the LED is ON versus OFF:

Because the RGB LED on this board is Active-Low, the relationship is inverted compared to a "normal" (Active-High) LED:

  • 0 duty = pin always LOW = LED always ON (full brightness)
  • 32767 duty = pin half HIGH, half LOW (50% brightness)
  • 65535 duty = pin always HIGH = LED always OFF

On an Active-High LED it would be the other way around: a higher duty cycle would mean a brighter LED.

Python — PWM Brightness Test 
import machine
import time

# Red LED = nRF52840 pin P0.24
red = machine.PWM(machine.Pin(24), freq=1000)

print("PWM brightness test...")

# Fade from bright to dim (Active-Low: 0 = bright, 65535 = off)
for duty in range(0, 65536, 5000):
    red.duty_u16(duty)
    print(f"Duty: {duty}")
    time.sleep(0.3)

red.duty_u16(65535)   # Make sure the LED ends fully OFF
print("Done!")

Part 3: The set_color() Function

Now let's combine everything into a reusable function that takes red, green, and blue values (0–100%) and handles Active-Low inversion automatically.

Python — set_color Function 
import machine
import time

# Setup PWM pins (RGB LED: Red = P0.24, Green = P0.16, Blue = P0.06)
red = machine.PWM(machine.Pin(24), freq=1000)
green = machine.PWM(machine.Pin(16), freq=1000)
blue = machine.PWM(machine.Pin(6), freq=1000)

def set_color(r, g, b):
    """Set RGB LED color. Values 0-100% (Active-Low inverted)."""
    # Invert for Active-Low: 100% requested = 0 duty (full brightness)
    red.duty_u16(int((100 - r) * 655.35))
    green.duty_u16(int((100 - g) * 655.35))
    blue.duty_u16(int((100 - b) * 655.35))

# Test colors
set_color(100, 0, 0)   # Pure Red
time.sleep(1)
set_color(0, 100, 0)   # Pure Green
time.sleep(1)
set_color(0, 0, 100)   # Pure Blue
time.sleep(1)
set_color(100, 100, 0) # Yellow (Red + Green)
time.sleep(1)
set_color(100, 100, 100) # White
time.sleep(1)
set_color(0, 0, 0)     # Off
time.sleep(1)
