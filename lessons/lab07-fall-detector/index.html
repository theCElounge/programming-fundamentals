Lab Fall Detector

Recognize the acceleration signature of a fall, combine layered logic thresholds, and explore the difference between polling and hardware interrupts.

Learning Objectives

By the end of this lab, you will be able to:

  1. Recognize the acceleration signature of a free-fall event.
  2. Combine multiple logic thresholds to distinguish a fall from normal motion.
  3. Understand the difference between polling and interrupts.
  4. Build a multi-stage detector: free-fall, followed by an impact spike.
  5. Trigger an alert (LED + message) when a fall pattern is detected.

Part 1: What Free-Fall Looks Like to an Accelerometer

This is the most counter-intuitive idea in the whole course: an object in free-fall reads close to 0 g on an accelerometer, not 1 g. Sitting still, gravity pushes the sensor's internal mass against its housing, which the chip reads as 1 g. During free-fall, the whole sensor and its internal mass are falling together — there's no relative force to measure, so the reading drops toward zero.

A real fall has a recognizable three-part signature:

  1. Rest — magnitude near 1.0 g.
  2. Free-fall — magnitude drops sharply, near 0.0 g, for a brief moment.
  3. Impact — magnitude spikes well above 1.0 g as the fall is stopped.

Detecting only a low reading, or only a high spike, causes false alarms — plenty of ordinary motions produce one or the other alone. A reliable detector looks for the low-then-high sequence.

Part 2: Combining Thresholds for a Reliable Detector

Building on Lab 6's magnitude and thresholding, we now need two thresholds and a short memory of what already happened:

Python — fall_detector.py 
import machine
import math
import time
from bmi270 import BMI270

i2c = machine.I2C(1, scl=machine.Pin(15), sda=machine.Pin(14))
imu = BMI270(i2c)

FREEFALL_THRESHOLD = 0.4   # g — below this, we may be falling
IMPACT_THRESHOLD = 2.5     # g — above this, right after a free-fall, is an impact
WATCH_WINDOW = 1.0         # seconds to watch for impact after a free-fall dip

falling_since = None

print("Fall detector armed. Ctrl+C to stop.")

while True:
    x, y, z = imu.read_accel()
    magnitude = math.sqrt(x**2 + y**2 + z**2)
    now = time.ticks_ms()

    if magnitude < FREEFALL_THRESHOLD and falling_since is None:
        falling_since = now
        print(f"Free-fall detected (magnitude={magnitude:.2f} g)...")

    elif falling_since is not None:
        elapsed = time.ticks_diff(now, falling_since) / 1000

        if magnitude > IMPACT_THRESHOLD:
            print("FALL DETECTED! Free-fall followed by impact.")
            falling_since = None

        elif elapsed > WATCH_WINDOW:
            # Too much time passed without an impact -- false alarm, reset
            falling_since = None

    time.sleep(0.02)

Walk through the logic: as soon as magnitude dips below FREEFALL_THRESHOLD, we start a timer (falling_since). If an impact spike arrives within WATCH_WINDOW seconds, we declare a fall. If nothing happens in time, we quietly reset and keep watching — this rejects momentary dips that aren't real falls.

Part 3: Polling vs. Interrupts

Every program you've written so far uses polling: a loop that repeatedly asks the sensor "what's your value right now?" This is simple and works well for a fall detector, but it has a real cost — the board is constantly busy checking, even when nothing is happening, which wastes power and can miss events that occur between checks if the loop is too slow.

Many real embedded systems instead use hardware interrupts: the sensor itself watches for a condition (like a sudden acceleration spike) and sends an electrical signal straight to the processor the instant it happens, which pauses whatever the processor was doing to handle the event immediately. The BMI270 chip actually supports this internally, but this course keeps things simple by polling — it's important to understand the trade-off even if we don't implement true interrupts here.

PollingInterrupts
How it worksLoop repeatedly checks the valueHardware signals the processor the instant an event occurs
Power useHigher — CPU is always activeLower — CPU can sleep between events
ComplexitySimple to write and reason aboutMore complex; requires careful, fast handler code
Timing precisionLimited by loop speed (time.sleep())Very precise — responds immediately
💡 Why we poll in this lab: A fast polling loop (time.sleep(0.02), i.e. 50 checks per second) is quick enough to reliably catch a fall, which typically takes several hundred milliseconds from free-fall to impact — plenty of time for polling to keep up.

Part 4: Adding a Visual Alert

Let's use what you learned in Lab 2 to flash the onboard RGB LED red when a fall is detected, in addition to the printed message.

Python — fall_detector_with_alert.py 
import machine
import math
import time
from bmi270 import BMI270

i2c = machine.I2C(1, scl=machine.Pin(15), sda=machine.Pin(14))
imu = BMI270(i2c)
# Red LED = nRF52840 pin P0.24 (see Lab 2)
red_led = machine.PWM(machine.Pin(24), freq=1000)
red_led.duty_u16(65535)   # start OFF (Active-Low)

def alert_flash():
    # Active-Low: 0 = on. Flash red 5 times.
    for _ in range(5):
        red_led.duty_u16(0)
        time.sleep(0.1)
        red_led.duty_u16(65535)
        time.sleep(0.1)

FREEFALL_THRESHOLD = 0.4
IMPACT_THRESHOLD = 2.5
WATCH_WINDOW = 1.0

falling_since = None
print("Fall detector armed. Ctrl+C to stop.")

while True:
    x, y, z = imu.read_accel()
    magnitude = math.sqrt(x**2 + y**2 + z**2)
    now = time.ticks_ms()

    if magnitude < FREEFALL_THRESHOLD and falling_since is None:
        falling_since = now

    elif falling_since is not None:
        elapsed = time.ticks_diff(now, falling_since) / 1000

        if magnitude > IMPACT_THRESHOLD:
            print("FALL DETECTED!")
            alert_flash()
            falling_since = None
        elif elapsed > WATCH_WINDOW:
            falling_since = None

    time.sleep(0.02)
