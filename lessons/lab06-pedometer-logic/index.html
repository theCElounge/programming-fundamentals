Lab 006 / 014 Lab 6 of 14

Lab Pedometer Logic

Compute acceleration magnitude, use comparisons and thresholding to filter noise, and combine conditions with logic gates to count steps.

Learning Objectives

By the end of this lab, you will be able to:

  1. Compute the total magnitude of acceleration from three axes.
  2. Use comparison operators to test sensor values against a threshold.
  3. Understand why raw sensor data needs thresholding to filter out noise.
  4. Combine conditions with logic gates (and, or, not).
  5. Detect and count steps from walking motion.

Lab Information

Hardware
BMI270 6-Axis IMU — Accelerometer (onboard, I2C)
Duration
60–90 minutes
Prerequisites
Lab 5: The Virtual Level
Key Concepts
Comparisons, thresholding, logic gates

Part 1: Measuring Total Motion

In Lab 5, you looked at each axis separately to find tilt. For counting steps, we care about something different: the overall intensity of movement, regardless of direction. That's the magnitude of the acceleration vector, found with the 3D distance formula:

magnitude = √(x² + y² + z²)
Python — magnitude_test.py 
import machine
import math
import time
from bmi270 import BMI270

i2c = machine.I2C(1)
imu = BMI270(i2c)

while True:
    x, y, z = imu.read_accel()
    magnitude = math.sqrt(x**2 + y**2 + z**2)
    print(f"magnitude = {magnitude:.2f} g")
    time.sleep(0.1)

Sitting still, the magnitude should hover right around 1.00 g (just gravity). Give the board a firm tap or shake it — the magnitude spikes well above 1.00 for a moment.

Part 2: Comparisons and Thresholding

Python's comparison operators (>, <, >=, <=, ==, !=) each evaluate to a boolean — True or False. We use them to ask: "is this reading big enough to count as a step?"

Python — Shell 
>>> magnitude = 1.45
>>> magnitude > 1.2
True
>>> magnitude < 1.0
False
>>> is_step = magnitude > 1.2
>>> is_step
True

The value we compare against — 1.2 in the example above — is called a threshold. Choosing a good threshold is the core challenge of this lab:

  • Threshold too low: tiny vibrations and sensor noise get counted as steps (false positives).
  • Threshold too high: gentle steps go undetected (false negatives).
🔬 Try it: Run the magnitude-printing loop from Part 1 while walking with the board in your hand. Note the typical peak values — that's your starting point for choosing a threshold.

Part 3: Logic Gates — Combining Conditions

A single threshold isn't quite enough to reliably detect a step — a value bouncing around the threshold can trigger many "steps" for a single real one. We need a condition with two parts: the magnitude must cross above a high threshold, and then drop back below a lower threshold, before we count the next step. Python's and, or, and not let us combine boolean conditions like this.

OperatorTrue when…Example
andBoth sides are Trueabove and not_counted
orAt least one side is Truetoo_high or too_low
notFlips True ↔ Falsenot stepped
Python — Shell 
>>> above_threshold = True
>>> already_counted = False
>>> above_threshold and not already_counted
True

Part 4: Building the Pedometer

Now let's combine magnitude, thresholding, and logic gates into a working step counter. We use a state flag (peak_active) so each footstep is only counted once, even though it stays above the threshold for several readings in a row.

Python — pedometer.py 
import machine
import math
import time
from bmi270 import BMI270

i2c = machine.I2C(1)
imu = BMI270(i2c)

STEP_THRESHOLD = 1.25   # g — tune this for your walking style
RESET_THRESHOLD = 1.05  # g — must drop below this before the next step counts

step_count = 0
peak_active = False

print("Start walking with the board... Ctrl+C to stop.")

while True:
    x, y, z = imu.read_accel()
    magnitude = math.sqrt(x**2 + y**2 + z**2)

    if magnitude > STEP_THRESHOLD and not peak_active:
        step_count += 1
        peak_active = True
        print(f"Step {step_count} detected! (magnitude={magnitude:.2f})")
    elif magnitude < RESET_THRESHOLD and peak_active:
        peak_active = False   # ready to detect the next step

    time.sleep(0.05)

Notice the two-threshold pattern (sometimes called hysteresis): using a high threshold to trigger and a separate, lower threshold to reset prevents one footstep's vibration from being counted multiple times.

🔧 Troubleshooting:
  • Counting way too many steps? Raise STEP_THRESHOLD or check that RESET_THRESHOLD is being reached between steps.
  • Missing real steps? Lower STEP_THRESHOLD slightly, or hold the board more rigidly (a loose grip absorbs motion).
